# 官方证据与版本规则

## 来源要求

- 只接受当前平台档案 `verified_domains` 中的 HTTPS 官方域名。
- 用户提供的 URL 也必须核验官方归属；不因“用户提供”而自动信任。
- 已核验页面中发现的新域名进入 `pending` 复核，不得自动入库。
- 搜索引擎只用于发现 URL，搜索摘要不得入库。
- 第三方媒体、论坛、培训机构、服务商、聚合站和 AI 生成文本一律拒绝；最多用于寻找官方 URL。
- 用户授权后台内容必须通过可见页面或正式导出导入，并标记 `account_scoped`；不得保存凭证。
- 登录页、验证码页或 JavaScript 动态空壳正文不足时必须拒绝入库；不得把页面标题当作规则。

## 来源优先级

同平台、同范围、同一规则冲突时按以下顺序处理：

1. 正式合同或法定政策。
2. 具体类目、履约或处罚规则。
3. 通用政策。
4. 官方操作指南。
5. 官方新闻公告。

范围更具体的有效规则优先于通用规则。不同国家、主体、类目或履约方式不是新旧冲突。

## 版本状态

- `current`：当前有效。
- `pending`：已发布但尚未生效。
- `superseded`：已被同范围新版本替代。
- `withdrawn`：官方撤回或页面明确失效。
- `review_required`：日期、范围或官方冲突无法自动判断。

新快照与当前版本内容哈希不同时生成新版本。旧版本保留，不参与普通查询。

## 历史时点

- `effective_at` 表示官方声明的生效日期，`observed_at` 表示本库首次观察时间。
- 历史问题按 `valid_from <= as_of_date < valid_to` 检索。
- 没有官方日期的旧页面只能以首次观察时间作为保守下界，并明确限制。
- 当前版本、历史有效版本和知识库发现时间不得混为同一个时间概念。

## 证据链

每个可回答规则版本必须能追溯到 `snapshot -> extracted_section -> evidence_link`。
回答引用应包含官方 URL、快照时间、章节标题、内容哈希和解析器版本。

## 新鲜度

每日运行条件请求增量更新；高风险规则 24 小时、普通规则 7 天。超过阈值先同步。同步失败时可以引用已保存版本，但必须显示最后核验时间和“未能实时复核”，不得声称最新。
